# Proposal

## Why

Exercises now come from the free exercise dataset imported by `ImportFreeExerciseCatalog_202610271200`, and from now on they are maintained directly in the database. Nobody uses the API's create, update and delete flows, or the aggregate methods behind them, and they leave a second way to change catalog data. Removing them makes exercises a catalog the application only reads.

Source brief: `.stpr/plan/openspec/proposal-change-exercises-read-only-catalog.md`.

## What Changes

- **BREAKING:** `POST /exercises`, `PUT /exercises/{id}` and `DELETE /exercises/{id}` are removed. Only `GET /exercises` and `GET /exercises/{id}` remain, unchanged
- **BREAKING:** the `Exercise` aggregate loses `Create`, `Update`, `SetTranslation`, `RemoveTranslation` and the `VideoUrl` and `Muscle` setters. `ExerciseTranslation` loses `Create` and `Rename`. Both keep `Rehydrate` and read-only properties only
- `CreateExerciseUseCase`, `UpdateExerciseUseCase`, `DeleteExerciseUseCase`, `ExerciseDTO`, `ExerciseTranslationDTO` and `ExerciseTranslationParser` are removed, together with their registrations
- `IExerciseRepository` keeps only `GetAll`, `GetAllByIds` and `GetById`. `Save`, `Delete` and `ExistsByFreeExerciseDbId` are removed, along with the translation reconcile
- `IWorkoutRepository.ExistsByExerciseId` is removed. Its only caller was the delete use case
- `FreeExerciseDbIdAlreadyExistsException` and `ExerciseInUseException` are removed, together with their `ExceptionMapper` mappings
- `ExerciseRequest` and `ExerciseTranslationRequest` are removed. `ExerciseResponse` is unchanged
- No schema, migration or data change

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `exercises`: exercises become read-only through the API. The write requirements (create, replace, dataset id immutability and uniqueness on writes, input validation, normalization) are removed. A new requirement states that writes are not served. Body part derivation is restated in terms of stored data. Canonical template reference: `ExerciseUseCase` (`src/WeightTracker.Application/UseCases/Exercises`), the read-only use case reference in `.stpr/template/README.md`

## Module Classification

- Exercises -> read-only catalog -> `src/WeightTracker.Application/UseCases/Exercises` (`ExerciseUseCase`)
  - This catalog is truly read-only, not just publicly read-only. After this change no endpoint, use case or domain behavior writes exercise state. Only migrations, direct database edits and the development/test seeder do
  - This is consistent with the invariants: the module is not called read-only "only because users cannot edit it", because no system behavior changes it either
- ExerciseTranslation -> part of the read-only catalog, loaded with its exercise
- Workouts -> mutable aggregate, unchanged. It references exercises by id

## Business Identifiers And Mutability

- `Exercise.Id`: immutable. It is assigned by the catalog migration or the seed, never generated by the application
- `Exercise.FreeExerciseDbId`: unique (`UQ_Exercises_FreeExerciseDbId`) and immutable from the application's point of view
- `ExerciseTranslation.Id` and (`ExerciseId`, `LanguageCode`): immutable from the application's point of view; the unique constraint stays

## Conflicts With Template Or Invariants

- None. The change moves Exercises from a mutable aggregate to the read-only catalog reference the template already names. No deviations are allowed

## Impact

- Domain: `Domain/Exercises/Exercise.cs`, `ExerciseTranslation.cs`
- Application: `UseCases/Exercises`, `Interfaces/IExerciseRepository.cs`, `Interfaces/IWorkoutRepository.cs`, `Exceptions`
- Infrastructure: `Repositories/ExerciseRepository.cs`, `Repositories/WorkoutRepository.cs`. `ExerciseMapper` keeps both directions, because `DatabaseSeeder` uses `MapToEntity`
- API: `ExercisesController`, `Dtos/ExerciseRequest.cs`, `Common/ExceptionMapper.cs`, `Program.cs`
- Template parity: the `.stpr/template` copies of `Exercise.cs`, `IExerciseRepository.cs` and any other copied file that changes
- Clients: any frontend or backoffice screen that creates, edits or deletes exercises stops working. Fixing those screens is not part of this change
- Tests: unit and integration suites covering exercise writes are removed or rewritten
