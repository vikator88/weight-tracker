# Proposal

## Why

Administrators can create users (`POST /users`) but cannot see who has an account. They need the full list of
users of every role. Trainers will later need the list of their athletes, but there is no explicit trainer–athlete
relationship yet, so the trainer branch is declared now and answered as not implemented until that relationship
exists.

## What Changes

- New protected route `GET /users`, open to callers whose stored role is `ADMIN` or `TRAINER`.
- `ADMIN`: `200 OK` with every user of every role, including the caller, ordered by email ascending. Each item
  carries `id`, `email`, `name`, `surname` and `role`, and nothing else.
- `TRAINER`: `501 Not Implemented` with no user data, until a trainer–athlete relationship exists.
- `USER`: `403 Forbidden`. Without a valid token: `401 Unauthorized`.
- A new application exception for the deliberately unimplemented trainer branch, mapped explicitly to `501`.
- `GET /users/me`, `PUT /users/me` and `POST /users` are unchanged.

## Module Classification And Identifiers

- `Users` is a mutable aggregate, not a catalog. This change adds a read path only; no new table or column.
- `User.Id` is the technical identifier, generated by `Id.New()`, immutable. Not affected.
- `User.Email` is the unique business identifier, immutable after creation. Not affected.

## Impact

- API: new `GET /users`; the OpenAPI document gains that operation, so the front's snapshot will need a refresh in
  its own plan.
- Code: `Application/UseCases/Users` (new use case), `Application/Interfaces/IUserRepository` and
  `Infra/Repositories/UserRepository` (new `GetAll`), `Application/Exceptions` (new exception),
  `Api/Common/ExceptionMapper` (new `501` mapping), `Api/Endpoints/Users/UsersController` (new action),
  `Program.cs` (registration). No domain or migration changes.
- Tests: unit tests for the use case, integration tests for the endpoint, exception mapper and OpenAPI document.

## Acceptance Criteria

- An `ADMIN` gets every user of the three roles, ordered by email, with only `id`, `email`, `name`, `surname`, `role`.
- A `TRAINER` gets `501` and no user data.
- A `USER` gets `403`; anonymous or invalid-token callers get `401`.
- All unit and integration tests pass.
